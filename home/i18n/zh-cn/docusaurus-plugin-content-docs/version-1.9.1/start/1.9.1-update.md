本指南仅适用于从已发布的 HertzBeat 1.9.0 升级到 1.9.1，不代表其他源码版本或未经验证的软件包组合兼容。开始前，请确认 Apache 官方发布渠道已提供 1.9.1 制品，并为当前部署选择匹配的软件包或镜像。

## 1.9.1 的变化

H2、MySQL 和 PostgreSQL 的 Flyway 迁移目录与正式 `v1.9.0` 发布版相同。1.9.1 没有新增 Flyway 迁移文件。1.9.1 的管理面访问策略要求手动检查账号，请参阅[仅管理员访问迁移说明](../help/admin_only_migration)。

随包提供的 `application.yml` 默认关闭 Digest 认证。如果继续使用已有或挂载的 `application.yml`，其中的 `sureness.auths` 配置会保留。替换镜像或软件包不会删除旧配置中的 `digest` 项，请明确检查正在使用的配置文件。

## 备份并准备制品

维护窗口前：

1. 记录正在运行的 Manager、Collector、数据库和部署版本，并保存可用于回滚的完整 1.9.0 软件包或镜像引用。
2. 备份元数据库。复制 H2 数据库前先停止 HertzBeat；MySQL 或 PostgreSQL 应使用一致性备份方式。
3. 备份 `application.yml`、`sureness.yml`、挂载配置、证书和密钥文件、`define/` 下的自定义模板以及 `ext-lib/` 中的自定义 JAR。按实际部署同时保存 Compose 文件、`.env`、Kubernetes 清单、ConfigMap 和 Secret。
4. 准备完整且匹配的 1.9.1 Manager 软件包或镜像，不要只替换主 JAR。如部署了远程 Collector，也从同一正式发布版本准备 1.9.1 Collector 制品，不要混用未经验证的构建。

## 迁移配置和账号

以 1.9.1 配置为参考，将部署专属设置合并进去。保留数据库凭据、`sureness.jwt.secret`、TLS 私钥和其他密钥。不要用示例配置覆盖生产环境挂载文件。除非单独审查了变更，否则应保留自定义模板和 `ext-lib/` 内容。

1.9.1 的管理 API 和界面要求精确的 `admin` 角色。升级前盘点 user、guest、自定义账号和自动化账号，只为可信的全实例管理员手动授予 `admin`。系统不会自动提权。旧 token 不能绕过后端的 admin-only 检查；管理角色或路由排除配置也不能让非 admin 账号重新获得管理面访问。按[仅管理员访问迁移步骤](../help/admin_only_migration)操作，并使用自己的账号配置进行演练。

Digest 默认值适用于 1.9.1 随包配置。如果部署继续沿用旧的 `application.yml`，请检查 `sureness.auths`；只有在符合预期认证策略时才移除 `digest`。修改生效配置后需重启。

## 升级并验证 Collector

Manager 和 Collector 仅使用来自同一已验证 1.9.1 发布版本的制品。启动后，在 HertzBeat 中确认每个远程 Collector 已连接，检查 Collector 日志，并验证一个已知监控项产生了新的采集数据。复查自定义 Collector 配置和挂载的 `ext-lib/` 依赖。

端口 `1158` 用于 Manager 与 Collector 之间的传输。仅允许可信 Collector 来源网络访问该端口。1.9.1 的管理 API 迁移不会改变或修复现有 Collector 传输协议的认证。

## 升级验收

恢复正常流量前，确认：

- Manager 显示预期的 1.9.1 构建版本，启动期间没有数据库或配置错误。
- 可信管理员可以登录并使用管理 API；不具备精确 `admin` 角色的账号会被拒绝。
- 每个远程 Collector 重新连接，代表性监控项产生新的数据。
- 正在使用的 `application.yml`、`sureness.yml`、自定义模板、密钥和 `ext-lib/` 与审查过的部署配置一致。
- 实际认证方式与 `sureness.auths` 列表一致，并确认是否有意启用了 Digest。

## 安全回滚

验收失败时，停止 HertzBeat 和受影响的 Collector。恢复完整的 1.9.0 软件包或镜像，以及对应备份的配置、模板和 `ext-lib/`。如果 1.9.1 运行期间写入过数据库，启动 1.9.0 前先恢复升级前的一致性数据库备份。不要只替换 JAR 回滚，也不要假定 1.9.1 写入的数据与所有早期构建兼容。升级验收通过前保留 1.9.1 期间创建的备份。
